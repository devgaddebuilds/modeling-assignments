## 2. Model (v1)

- Outcome: no-show (positive class) vs checked-in
- Model family: classification tree (scikit-learn `DecisionTreeClassifier`, Gini)
- Features offered to the tree: lead_time_days, prior_no_shows, age, distance_miles, sms_reminder, new_patient, appointment_hour
- Depth: 2 (max_depth = 2), leaves: 4, minimum 10 training appointments per leaf
- Class weights: no-show errors count 2x, matching the cost table ($120 empty slot vs $60 double booking). In effect a leaf is called no-show when more than one third of its training appointments were no-shows.
- Features the tree splits on, root first: sms_reminder, prior_no_shows
- Features offered but never used: lead_time_days, age, distance_miles, new_patient, appointment_hour
- Root split: sms_reminder <= 0.5
